# Frontend

Vue 3 во `frontend/`. Стек и разрез приложений — [ADR 0005](../docs/architecture/adr/0005-tech-stack.md) и
[ADR 0008](../docs/architecture/adr/0008-client-mini-app.md). Внешний вид —
[ADR 0009](../docs/architecture/adr/0009-ui-design-figma.md).

## Пакеты

Три каталога — пакеты одного pnpm workspace. Общий код приложений — только `api-client/`.

- `dashboard/` — кабинет тренера в браузере: PrimeVue и Pinia. Пакета ещё нет, он появляется вместе с экранами кабинета.
- `miniapp/` — Mini App клиента в WebView Telegram: свои экраны, `@tma.js/sdk` и `@tma.js/sdk-vue`.
- `api-client/` — типы и клиент `openapi-fetch` по снимку OpenAPI Django.

Кабинет не импортирует `@tma.js`. Mini App не импортирует PrimeVue и не подключает второй UI-кит. Общий каталог
компонентов не заводится: ширина, тема и вход у приложений разные. `dashboard/` и `miniapp/` не импортируют друг друга.

Графики Mini App — Chart.js напрямую. Зависимость добавляется в тот пакет, которому она нужна, и фиксируется в его
`package.json`.

## Макеты

Источник внешнего вида кабинета и Mini App — файл Figma Design. Скриншот, картинка в репозитории, описание в чате и
`design.md` OpenSpec его не заменяют.

Новый экран и заметное изменение интерфейса сначала появляются в этом файле редактируемыми слоями, затем во `frontend/`.
Задача не закрыта, пока макета в файле нет.

Макет собирает и правит агент через Figma AI. Картинка в ответе макетом не считается. Слои нужно просмотреть в файле:
результат черновой, пока его не приняли.

Макет кабинета собирается из PrimeVue. Макет Mini App — на цветах темы Telegram, без второго UI-кита.

Чат бота остаётся диалогом. Его тексты и шаги задаёт спецификация. Figma не входит в продукт: Trenly в рантайме её не
вызывает.

## Экраны

Поведение для пользователя меняется через спецификацию OpenSpec. Имена в коде берутся из глоссария, поле «В коде». Текст
на экране — по-русски.

Объём Mini App задаёт ADR 0008: дневник и итог за день, тренировки по дням, статистика посещённых тренировок. Другой
экран клиента сначала попадает в это решение: чат бота или Mini App.

## Компоненты

Однофайловый компонент на Composition API, `<script setup lang="ts">`. Правила —
[руководство Vue](https://vuejs.org/style-guide/) и [`<script setup>`](https://vuejs.org/api/sfc-script-setup.html).
Options API не используется. Корневой компонент приложения — `App.vue`.

- Файл, имя и тег в шаблоне — PascalCase из двух и более слов: `ClientListView.vue`, `<ClientListView />`.
- Экран маршрута лежит в `src/views/` и называется `{Имя}View`. Маршрут объявлен в `src/router.ts`, его имя совпадает с
  view.
- Компонент этого приложения лежит в `src/components/` и делает одно дело.
- Повторяемая логика без разметки — `src/composables/use{Имя}.ts`.
- Вход — `defineProps` с аргументом-типом. Необязательный проп получает значение через `withDefaults`. Событие —
  `defineEmits` с именованным кортежем: `change: [id: number]`. Тип и рантайм-объявление в одном вызове не смешиваются.
- Проп в скрипте — camelCase, в шаблоне — kebab-case.
- У `v-for` есть устойчивый `:key` — id записи. `v-if` и `v-for` стоят на разных элементах.
- Выражение в шаблоне короткое. Расчёт живёт в `computed` или в функции.
- Стили компонента — `<style scoped>`. Цвета Mini App читаются из CSS-переменных темы Telegram, которые выставляет
  `@tma.js/sdk-vue`. Кнопки оболочки Telegram — `MainButton` и `BackButton`.
- Текст ответа API вставляется как текст.
- Комментарий объясняет неочевидное ограничение и пишется по-русски. Подпись к функции, которую уже описывает тип, не
  нужна.

## Состояние

Стор — по [Pinia](https://pinia.vuejs.org/getting-started.html). В него попадает то, что нужно нескольким экранам или
должно пережить смену маршрута. Состояние одного экрана остаётся в компоненте. Стор — setup-функция `defineStore`,
модуль `src/stores/use{Имя}Store.ts`.

- Кабинет: `useAuthStore` хранит сессию. Токен доступа лежит в памяти стора, токен обновления — в `localStorage`. Список
  клиентов живёт в `ClientListView`, пока он нужен одному экрану.
- Mini App: Pinia хранит только токен клиента.
- Стор не вызывает Django мимо `api-client` и не повторяет правило, которое уже проверяет API.

## Вход в кабинет

Маршруты кабинета закрывает `beforeEach`: без токена доступа открыт только экран входа. Вход — телефон и пароль, дальше
пара токенов. Токен обновления сам кабинет не открывает: им получают новую пару.

`Authorization: Bearer` подставляет клиент API. Представление не собирает URL и не описывает тело ответа.

## API

Приложение вызывает Django только через `createApiClient` из `api-client`.

- `openapi.json` и `src/schema.d.ts` не правятся руками. Снимок снимает `spectacular`, типы пишет
  `pnpm --filter api-client generate`. Оба файла коммитятся вместе с изменением контракта. Команды — в корневом README.
- Поле запроса и ответа называется так, как в схеме. Отдельный тип тела рядом со схемой не объявляется.
- Токен доступа тренера и токен клиента передаются как `Authorization: Bearer`.
- Mini App один раз меняет `initData` на токен клиента и дальше ходит в Django сам. Вне Telegram `init` не роняет
  страницу: остаётся запасной фон.

## TypeScript

Включены `strict` и `verbatimModuleSyntax`. Импорт типа пишется `import type`. `any` не используется. Сборка приложения
запускает `vue-tsc --noEmit` до `vite build`.

## Оформление

Отступ в `js`, `ts`, `vue` и `css` — два пробела. Длина строки — 120 символов. Форматирует Prettier из каталога
`frontend/`.

## Границы

- Экран показывает данные и ошибку ответа. Правило записи проверяет бэкенд.
- Инстанс Chart.js оборачивается в `markRaw`.
- В `main.ts` кабинета `app.config.errorHandler` пишет ошибку в лог. Отдельный сервис ошибок не подключается.
- Связь экранов идёт через пропы, события и Pinia. Общая шина событий, mixins, provide/inject для темы, PWA, service
  worker, Web Workers и IndexedDB не заводятся.
- `v-memo`, `shallowRef` и ленивая подгрузка маршрута появляются, когда список или бандл этого потребуют.
- Vitest появляется вместе с нетривиальным composable. На каркас кабинета тесты не ставятся.
- Пакет `dashboard/` не создаётся, пока задача не про экраны кабинета.
