# Design

## Context

См. [proposal.md](proposal.md). Каталога `frontend/` нет. Схема API лежит на `GET /api/schema/`, drf-spectacular уже установлен. Кабинет в этом изменении не собирается: пакет `dashboard/` появится вместе с экранами входа и списка. C4 уже указывает `frontend/dashboard/` и `frontend/miniapp/`; каталог кабинета остаётся будущим.

## Goals / Non-Goals

**Goals:**

- Собрать pnpm workspace с оболочкой Mini App и пакетом клиента API.
- Сгенерировать типы из схемы Django, чтобы следующий экран подключал готовый клиент.
- Запустить оболочку Mini App локально, без вызова Django.

**Non-Goals:**

- Кабинет тренера: пакет `dashboard/`, форма входа, список клиентов, PrimeVue, Pinia, токен и прокси Vite.
- Экраны анкеты, дневника, истории, наград, графиков и отчёта.
- Вход клиента и обмен `initData`.
- Chart.js, CORS, деплой и CI. Хостинг ещё не выбран.

## Decisions

### Каталоги

Workspace — `frontend/`, не корень репозитория. Так `backend/` и `tg_bot/` остаются отдельными приложениями со своими зависимостями ([ADR 0003](../../../docs/architecture/adr/0003-monorepo.md)).

| Пакет | Содержимое |
|---|---|
| `frontend/miniapp/` | Оболочка: Vue 3, TypeScript, Vite, vue-router, `@tma.js/sdk`, `@tma.js/sdk-vue` |
| `frontend/api-client/` | `openapi-typescript` и `openapi-fetch` |

Версии — актуальные стабильные на момент реализации, фиксируются в `package.json`. Chart.js и PrimeVue не ставятся.

### Схема и клиент

Схему снимает уже установленный drf-spectacular, без запущенного сервера:

```bash
cd backend && uv run python manage.py spectacular --file ../frontend/api-client/openapi.json
```

Дальше `openapi-typescript` пишет типы, `openapi-fetch` готов ходить по ним. Снимок схемы и сгенерированные типы коммитятся. Команда регенерации описана в README. Новых путей API нет, контракт бэкенда не меняется.

Mini App пакет `api-client` не импортирует: вызывать Django пока нечем.

### Mini App

Приложение монтируется и красит страницу цветом темы Telegram через `@tma.js/sdk-vue`. На экране одна заглушка: Mini App клиента ещё без данных. Вызова Django и хранилища токена нет.

Вне Telegram `init` не должен ронять страницу: локальный `pnpm dev` показывает ту же заглушку на запасном фоне. Проверка — сборка пакета.

### Backend

Без изменений. Экспорт схемы — команда spectacular, которая уже ставится с drf-spectacular.

### tg_bot

Без изменений. Mini App в этом изменении бота не вызывает.

### Документация

Модель данных не меняется, спецификация поведения не пишется, новый ADR не нужен: стек уже в ADR о Mini App.

У этого ADR и у ADR «тренер не является учётной записью Django» сейчас один номер 0007. Файл Mini App переименовывается в `0008-client-mini-app.md`, реестр и ссылки на него обновляются. Ссылка из `docs/nfr/security.md` на ADR про учётку тренера остаётся на прежнем файле.

README получает дерево `frontend/` и команды: установка pnpm, генерация клиента, `pnpm dev` Mini App.

## Risks / Trade-offs

- [Клиент API пока никто не импортирует] → типы уже лежат в репозитории, кабинет и экраны Mini App подключат пакет следующим изменением.
- [Снимок OpenAPI отстаёт от кода] → регенерация — явная команда в README.
- [В ADR три каталога, а `dashboard/` появится позже] → этот разрыв закрывает изменение кабинета, не оболочка.
- [SDK Telegram вне WebView ведёт себя иначе] → оболочка ловит отсутствие Telegram и всё равно показывает заглушку.

## Migration Plan

Новый каталог, данных для переноса нет. Откат — удалить `frontend/` и правки README и номера ADR. API не меняется.
