# 0007. Тренер не является учётной записью Django

- **Статус:** Принято
- **Дата:** 2026-11-12
- **Связанные изменения:** openspec/changes/add-trainer-and-client

## Контекст

В кабинет входит тренер, в Django Admin — администратор. Это разные роли: тренер не должен попасть в админку, даже если кто-то ошибётся с флагом доступа. Администратор при этом не является тренером и не должен попадать в список тренеров.

## Рассмотренные варианты

1. **Одна модель `User` с `is_staff=False` у тренера.** Вход в админку и в кабинет общий. Флаг можно включить, и тренер окажется в админке.
2. **`AUTH_USER_MODEL` — тренер.** Тогда сотрудник Trenly тоже был бы тренером либо пришлось бы плодить пустые анкеты.
3. **Разные учётки.** Администратор остаётся стандартным `User`. У тренера собственная модель с телефоном и хешем пароля. Форма `/admin/` ищет только `User`.

## Решение

Тренер — модель `Trainer`, не `User`. `AUTH_USER_MODEL` не меняется. Администратор входит в Django Admin как `User` со `is_staff`. Тренер входит в API кабинета телефоном и паролем и дальше передаёт Bearer-токен. Эти учётные данные к админке не подходят.

## Последствия

- Блокировка тренера не связана с флагами Django-пользователя.
- Вход в кабинет — отдельный эндпоинт, его нельзя получить включением `is_staff`.
- Сброс `SECRET_KEY` завершает выданные токены тренеров.
