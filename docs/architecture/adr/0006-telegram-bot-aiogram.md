# 0006. Telegram-бот на aiogram 3

- **Статус:** Принято
- **Дата:** 2026-11-10
- **Уточнено:** 2026-11-16
- **Связанные требования:** BR-001, BR-002, BR-003, BR-004
- **Дополняет:** [ADR 0003](0003-monorepo.md), [ADR 0005](0005-tech-stack.md)

## Контекст

Клиент общается с Trenly в Telegram, а те же данные смотрит тренер в кабинете. Клиент, анкета, дневник питания и
тренировки — один домен, он живёт в Django и PostgreSQL.

Помимо чата у клиента будет Mini App. Экраны Mini App и кабинет тренера вызывают API Django напрямую. Бот эти запросы не
проксирует.

Нужно выбрать библиотеку бота, где лежит его код и как он обменивается данными с Django.

## Рассмотренные варианты

1. **Процесс внутри `backend/`** — management-команда на Django, прямой доступ к моделям. Меньше сетевых вызовов, но
   цикл чата делит процесс и деплой с API кабинета.
2. **Отдельный сервис со своей копией доменной базы и брокером** — aiogram хранит клиентов и дневник у себя, Kafka
   развозит изменения в Django. Два источника одних и тех же записей: кабинет и чат видят данные с лагом.
3. **Отдельное приложение `tg_bot/` на aiogram 3, связь по HTTP** — домен остаётся в Django. Бот знает внутренний API,
   шаг диалога и черновик текущей пачки ответов.
4. **Та же схема папок с python-telegram-bot или pyTelegramBotAPI** — тот же разрез процессов, другая библиотека
   диалогов.
5. **Свои обработчики и FSM aiogram, без отдельной библиотеки окон** — нет новой зависимости, шаги, кнопки и стек
   диалогов пишем сами.

## Решение

Принимается вариант 3. Окна диалога собираются библиотекой `aiogram_dialog`, а не своими обработчиками поверх FSM
(вариант 5).

- В монорепозитории появляется приложение `tg_bot/` со своими зависимостями, сборкой и деплоем. Состав репозитория из
  ADR 0003 дополняется этой папкой.
- Библиотека бота — aiogram 3. Окна, кнопки и шаги диалога — `aiogram_dialog` 2.x с PyPI. На момент решения это 2.6.0. В
  зависимостях фиксируется релиз, не ветка `develop`.
- Бот не импортирует модели Django и не подключается к PostgreSQL.
- В Django уходят пачки ответов и действия, которые меняют запись. Клиент в запросе задаётся `telegram_user_id`.
  Промежуточный вопрос анкеты сам по себе запрос не вызывает.
- Формулировки вопросов и кнопок чата живут в боте. Django возвращает данные и исход: принято или код отказа. Бот
  собирает из этого фразу и вызывает Bot API. Токен бота хранится только в `tg_bot`.
- По id приглашения из ссылки Django отдаёт тренера: id, имя, фамилию и аватар. Клиента этот запрос не создаёт. Бот сам
  формулирует вопрос привязки.
- Анкета собирается в боте: имя, фамилия, рост, вес, цель. В конце клиент подтверждает тренера по ссылке и сохраняет
  анкету.
  Одним запросом Django создаёт клиента с этими данными и привязывает его к этому тренеру. До подтверждения клиента в
  списке нет.
- Запрос к внутреннему API содержит сервисный токен. Webhook бота проверяется `secret_token` Telegram.
- Локально бот забирает апдейты через polling. В окружениях Telegram вызывает webhook.
- Состояние окон `aiogram_dialog` лежит в FSM-хранилище aiogram в Redis: шаг, стек окон и черновик текущей пачки. Для
  анкеты это ответы до создания клиента. Для еды это ключ объекта и числа КБЖУ до ответа клиента. Записи клиента и
  дневника в Redis не пишутся.
- Распознавание КБЖУ выполняется в Django. Бот загружает сжатое фото в бакет ([ADR 0002](0002-photo-storage.md)),
  передаёт ключ объекта, получает числа и исход и сам формулирует вопрос подтверждения.

## Последствия

- Перезапуск бота не останавливает API кабинета, и наоборот.
- Контракт внутреннего API фиксируется вместе с остальным API Django. В чат уходят пачки и действия с записью, не каждый
  нажатый символ.
- Пока Django не подтвердил пачку, бот не пишет пользователю, что она сохранена.
- Повторный запрос с тем же ключом пачки не создаёт вторую запись.
- Фоновые задачи выбираются отдельно. Django сообщает, что спросить клиента и про какое занятие. Фразу вопроса за день
  до занятия собирает бот. Это отдельное сообщение в чате: оно не закрывает открытый диалог еды и не стирает его
  черновик.
- Канал Mini App, разрез экранов и обмен `initData` на токен клиента зафиксированы в
  [ADR 0008](0008-client-mini-app.md).
