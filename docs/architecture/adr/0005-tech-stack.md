# 0005. Технологический стек

- **Статус:** Принято
- **Дата:** 2026-11-09

## Контекст

Нужно выбрать стек для бэкенда (API кабинета тренера, Telegram-бот, интеграции), базы данных, админки и кабинета тренера. Команда хорошо знает Python, опыта фронтенд-разработки мало. Данные должны храниться в РФ (NFR-PRIV-003).

## Рассмотренные варианты фронтенда

1. **Vue 3** — лёгкий фреймворк, компоненты похожи на обычный HTML.
2. **HTMX + шаблоны Django** — минимум JavaScript, но API для кабинета не нужен, и при появлении других клиентов его придётся делать отдельно.
3. **React** — самый популярный, но выше порог входа.

## Решение

| Часть | Технологии |
|---|---|
| Бэкенд | Python, Django, Django REST Framework; drf-spectacular для OpenAPI-схемы |
| База данных | PostgreSQL: локально в Docker Compose, в окружениях — управляемый PostgreSQL у российского провайдера |
| Админка | Django Admin: администратор добавляет и блокирует тренеров (BR-011) |
| Кабинет тренера | Vue 3 + TypeScript, Vite, PrimeVue (готовые компоненты), Pinia (состояние) |

Фронтенд генерирует типы и клиент API из OpenAPI-схемы бэкенда. Версии — актуальные стабильные, фиксируются в зависимостях проекта.

## Последствия

- Админка доступна практически без разработки — достаточно настроить модели в Django Admin.
- API-контракт генерируется из кода; изменения контракта сразу видны во фронтенде как ошибки типов.
- Кабинет собирается в основном из готовых компонентов PrimeVue.
- Хостинг базы и бэкенда должен быть в РФ.
- Библиотека Telegram-бота и фоновые задачи выбираются отдельно.
