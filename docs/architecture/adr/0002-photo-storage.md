# 0002. Хранение фото еды в Yandex Object Storage

- **Статус:** Принято
- **Дата:** 2026-11-09
- **Связанные требования:** BR-004

## Контекст

Клиент отправляет фото еды в Telegram-бота для оценки КБЖУ. Тренер должен видеть эти фото в кабинете. Пользователи находятся в России; фото, привязанные к клиенту и его дневнику питания, считаем персональными данными, поэтому по 152-ФЗ они должны храниться на территории РФ. На старте нужен минимальный бюджет.

## Рассмотренные варианты

1. **Yandex Object Storage** — S3-совместимое, данные в РФ, бесплатно 1 ГБ хранения в месяц, далее ≈2,4 ₽ за ГБ.
2. **Cloudflare R2** — бесплатно 10 ГБ, но данные хранятся за рубежом; не подходит по 152-ФЗ.
3. **Не хранить фото, использовать `file_id` Telegram** — бесплатно, но срок хранения файлов Telegram не гарантирует, идентификаторы привязаны к боту.

## Решение

Фото хранятся в Yandex Object Storage:

- бэкенд получает фото от Telegram, сжимает до 1280 px по длинной стороне (JPEG) и загружает в закрытый бакет;
- в базе хранится ключ объекта, а не сам файл;
- кабинет тренера получает фото по временным подписанным ссылкам;
- фото удаляются через 90 дней правилом жизненного цикла бакета; распознанные КБЖУ в дневнике хранятся бессрочно.

Работа с хранилищем идёт через S3 API, чтобы при необходимости сменить провайдера без переписывания кода.

## Последствия

- Бесплатного объёма хватит примерно на пилот (по оценке ~25 МБ на клиента в месяц); дальше расходы небольшие.
- Решение временное: пересматривается при росте объёмов или смене требований.
- Срок хранения 90 дней нужно согласовать с продуктом: старые фото тренеру будут недоступны.
