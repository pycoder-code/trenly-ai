# 0003. Монорепозиторий

- **Статус:** Принято
- **Дата:** 2026-11-09

## Контекст

Trenly состоит из документации со спецификациями OpenSpec, бэкенда (API кабинета, Telegram-бот, интеграции) и фронтенда (кабинет тренера). Большинство доработок сквозные: меняют требования, бэкенд и фронтенд одновременно. Команда на старте небольшая.

## Рассмотренные варианты

1. **Три репозитория рядом** — каждому разработчику нужно клонировать все три и открывать общее рабочее пространство; облачные агенты и CI не видят документацию.
2. **Три репозитория, документация подключена submodule** — документация доступна в каждом сервисе, но закреплена на коммите и требует обновления; одна доработка — три pull request.
3. **Монорепозиторий** — всё в одном репозитории.

## Решение

Один репозиторий: `docs/`, `openspec/`, `backend/`, `frontend/`. Одна доработка — одно изменение OpenSpec и один pull request.

- Бэкенд и фронтенд — независимые приложения со своими зависимостями, сборкой и деплоем.
- CI запускает проверки только для изменённой части (фильтры по путям).
- Локальная инфраструктура (БД, S3-хранилище) поднимается одной командой.

## Последствия

- ИИ-агенты, CI и облачные агенты видят требования и код вместе.
- Синхронизация документации между репозиториями не нужна.
- Нельзя разграничить права доступа по частям; при росте команды бэкенд или фронтенд можно вынести в отдельный репозиторий.
