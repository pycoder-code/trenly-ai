# 0008. Mini App клиента и кабинет тренера в браузере

- **Статус:** Принято
- **Дата:** 2026-11-12
- **Связанные требования:** BR-003, BR-004, BR-006, BR-007, BR-009, BR-010
- **Дополняет:** [ADR 0005](0005-tech-stack.md), [ADR 0006](0006-telegram-bot-aiogram.md)

## Контекст

У Trenly два интерфейса с данными клиента. Тренер смотрит их в кабинете. Клиент часть действий делает в чате бота, а анкету, дневник, историю, награды и отчёт должен видеть на экране.

[ADR 0005](0005-tech-stack.md) фиксирует кабинет как Vue 3 в браузере. [ADR 0006](0006-telegram-bot-aiogram.md) оставляет боту чат и заранее говорит, что экраны Mini App вызывают API Django напрямую. [BR-009](../../business/requirements.md) не включает мобильное приложение тренера. Кабинет открывается только в браузере.

Команда мало пишет фронтенд. PrimeVue подходит кабинету и плохо подходит узкому WebView Telegram.

## Рассмотренные варианты

1. **Один Vue-проект и PrimeVue на оба интерфейса.** Общие компоненты, но кабинет и WebView Telegram расходятся по ширине, теме и входу.
2. **Кабинет тренера тоже как Mini App.** Тренер тогда привязан к Telegram, хотя кабинет по BR-009 живёт в браузере.
3. **Mini App ходит в Django только через бота.** Бот проксирует каждый экран. Это спорит с ADR 0006: бот не проксирует запросы экранов.
4. **Два приложения Vite во `frontend/` и общий клиент OpenAPI.** Кабинет — браузер, PrimeVue, телефон и пароль. Mini App — WebView Telegram. Токен бота остаётся в `tg_bot`: Mini App один раз обменивает `initData` на токен клиента и дальше читает API Django сам.

## Решение

Принимается вариант 4.

Во `frontend/` три каталога:

| Каталог | Назначение |
|---|---|
| `dashboard/` | Кабинет тренера |
| `miniapp/` | Mini App клиента |
| `api-client/` | Типы и клиент API из OpenAPI Django |

### Стек

Оба приложения собираются на Vue 3, TypeScript, Vite и vue-router. Три каталога — пакеты одного pnpm workspace, без отдельного монорепо-раннера.

| Часть | Библиотеки |
|---|---|
| Кабинет | PrimeVue, Pinia. Графики отчёта — Chart.js через графики PrimeVue |
| Mini App | `@tma.js/sdk` и `@tma.js/sdk-vue`: `initData`, цвета темы, `MainButton`, `BackButton`. Экраны свои, на цветах темы Telegram. Pinia хранит только токен клиента. Графики — Chart.js напрямую |
| Общий клиент | `openapi-typescript` и `openapi-fetch` по схеме drf-spectacular |

Готовый набор компонентов в стиле Telegram собран под React. Во Vue такого набора нет, поэтому Mini App не подключает второй UI-кит и не берёт PrimeVue.

Кабинет тренера открывается в браузере. Вход — телефон и пароль, дальше `Authorization: Bearer`.

Mini App клиента на текущем объёме показывает анкету, дневник и итог за день, историю тренировок, награды, графики и отчёт. Чат бота остаётся для подключения по ссылке или QR, фото еды, отметки «приду / не приду», напоминаний, сообщений тренера и кнопки «открыть Mini App».

Вход клиента:

1. Mini App передаёт `initData` в `tg_bot`.
2. `tg_bot` проверяет подпись токеном бота.
3. `tg_bot` запрашивает у Django токен клиента по `telegram_user_id` через внутренний API и сервисный токен.
4. Mini App дальше вызывает API Django с `Authorization: Bearer`.

Данные экранов бот не проксирует. Токен бота в Django не хранится. Срок токена клиента задаётся вместе с API этого входа.

## Последствия

- В Django два входа: тренер и клиент. Класс аутентификации тренера клиенту не подходит.
- Пока клиент не привязан к `telegram_user_id`, Mini App некого впускать. Каркас кабинета может появиться раньше, на входе тренера и списке его клиентов.
- Чтобы открыть Mini App, `tg_bot` должен быть доступен. Уже выданный токен клиента ходит в Django без бота.
- Глоссарий, контекст, контейнеры и формулировки канала в BR-003, BR-004, BR-006, BR-007 и BR-010 описывают этот разрез.
- Новый экран клиента сначала попадает в это решение: чат или Mini App. Сейчас в Mini App только перечисленный объём.
- Смена контракта OpenAPI видна обоим приложениям как ошибка типов в `api-client/`.
